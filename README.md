# CRM — система управления клиентами

Учебный Django-проект для учёта услуг, рекламных кампаний, потенциальных клиентов, контрактов и активных клиентов.

## Возможности

- Авторизация и выход пользователя.
- CRUD-операции для услуг, рекламных кампаний, потенциальных клиентов и контрактов — в соответствии с назначенными правами.
- Создание активного клиента на основе потенциального клиента с оформлением контракта.
- Статистика рекламных кампаний: потенциальные клиенты, активные клиенты, сумма контрактов, рекламный бюджет и соотношение дохода к рекламным расходам.
- Разграничение доступа с помощью стандартных Django permissions и групп.
- Административная панель Django для управления пользователями, группами и разрешениями.

## Технологии

- Python 3.11+
- Django 5.2
- SQLite для быстрого локального запуска; PostgreSQL можно использовать при соответствующей настройке проекта.
- HTML, CSS и шаблоны Django.

## Структура проекта

- `config/` — настройки Django и корневые URL-маршруты.
- `services/` — услуги.
- `campaigns/` — рекламные кампании и статистика.
- `leads/` — потенциальные клиенты.
- `contracts/` — контракты.
- `active_clients/` — активные клиенты.
- `templates/` — HTML-шаблоны.
- `static/` — статические файлы.
- `manage.py` — утилита управления Django.
- `.env.example` — пример переменных окружения.
- `requirements.txt` — зависимости проекта.

## Требования

- Python 3.11 или новее.
- `pip`.
- Git — если проект клонируется из репозитория.

## Установка и запуск

### Linux / WSL

Клонируйте репозиторий и перейдите в каталог проекта:

```bash
git clone https://github.com/shahverdiyevashahla1997/CRM.git
cd CRM
```

Создайте и активируйте виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate
```

Установите зависимости и создайте локальный файл настроек:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

Перед запуском проверьте `.env` и `config/settings.py`. Для локального запуска можно использовать SQLite, если настройки проекта оставляют `DB_NAME` незаданной.

Выполните миграции, создайте администратора и группы ролей:

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_roles
```

Запустите сервер разработки:

```bash
python manage.py runserver
```

Откройте сайт: <http://127.0.0.1:8000/>

Административная панель: <http://127.0.0.1:8000/admin/>

### Windows PowerShell

После установки Python откройте PowerShell в каталоге проекта и выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_roles
python manage.py runserver
```

Если PowerShell запрещает активацию виртуального окружения, можно открыть командную строку (cmd) и выполнить `.venv\Scripts\activate.bat`.

## Роли и права доступа

Команда `python manage.py seed_roles` создаёт группы:

- **Оператор** — просмотр, создание и изменение потенциальных клиентов.
- **Маркетолог** — просмотр, создание и изменение услуг и рекламных кампаний.
- **Менеджер** — просмотр потенциальных клиентов, управление контрактами и активными клиентами, просмотр кампаний и статистики.
- **Просмотр статистики** — доступ к аналитике для сотрудников, которым назначена эта группа.

Администратора создают командой `python manage.py createsuperuser`. Пользователями, группами и разрешениями можно управлять через `/admin/`. Удаление записей не предоставляется обычным ролям по умолчанию; разрешения можно изменить в административной панели.

## Проверка проекта

Из корневого каталога проекта выполните:

```bash
python manage.py check
python manage.py test
python manage.py makemigrations --check --dry-run
```

Последняя команда проверяет, не появились ли изменения моделей, для которых ещё не созданы миграции.

## Примечания

- Это учебный проект, а не готовая production-система. Перед реальным использованием необходимо настроить HTTPS, резервное копирование, журналирование и аудит действий, ограничения загрузки файлов и безопасное хранение секретов.
- Не добавляйте `.env`, виртуальное окружение и локальную базу данных в Git. Для секретов используйте локальный `.env`; в репозитории храните только `.env.example` без реальных паролей и ключей.
- Денежные поля используют `DecimalField`.
- Статистика суммирует суммы контрактов, связанных с активными клиентами, привлечёнными соответствующей кампанией. Для показателя дохода к расходам рассчитывается процент покрытия рекламного бюджета; при нулевом бюджете показатель отображается как «—».
- Для дополнительной проверки стиля кода, если `pylint` установлен, можно выполнить:

```bash
pylint --load-plugins pylint_django config services campaigns leads contracts active_clients
```
